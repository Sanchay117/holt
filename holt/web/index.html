How a run works

  1. Guard. Otari's prompt-injection guardrail checks the issue before any model reads it. A flagged issue is quarantined.
  2. Scout (small open-weight model) classifies it and plans the investigation.
  3. Researcher searches the web, fetches pages and asks the repo's DeepWiki over MCP, all run by the gateway.
  4. Analyst scores duplicates and reproduces snippets in Otari's code sandbox.
  5. Writer drafts the report through an Otari routing policy that falls back if a provider fails.

Every call is billed to you as an Otari end user, so your own budget caps what you can spend.
