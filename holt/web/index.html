How a run works

Every model call, tool run and dollar goes through Otari. Nothing talks to a provider directly.

  1. Guard Otari guardrail · block

    Checks the issue for prompt injection before any model reads it. A flagged issue is quarantined.

  2. Scout open-weight model

    Classifies the issue and plans the investigation.

  3. Researcher parallel open-weight model

    Web search, web fetch and the repo's DeepWiki over MCP, all run by Otari.

  4. Analyst parallel open-weight model

    Scores duplicates and reproduces snippets in Otari's code sandbox.

  5. Writer routing policy

    Drafts the report through a routing policy that falls back if a provider fails.

Each call is billed to you as an Otari end user, so your own budget caps what you can spend.
